# KONI-PRISM-Study: audit artifact package for an on-premise multimodal RAG system

Evaluation code, benchmarks, raw results and provenance records for the article
*Engineering and auditing an on-premise multimodal RAG system: performance, failure modes, and
lessons learned* (submitted to PeerJ Computer Science).

- Version: 1.1.1
- Archive: https://doi.org/10.5281/zenodo.23029708 (concept DOI, resolves to the latest version)
- Source: https://github.com/gwleee/KONI-PRISM-Study

## Description

The article audits a fully on-premise multimodal retrieval-augmented generation (RAG) system. It
measures the system's operational behaviour on an NVIDIA A100 80 GB server and tests the design
assumption behind each of its four mechanisms: resource-aware routing, conflict screening, tiered
memory and attribution.

This package contains everything needed to inspect and re-derive the reported results:

- the evaluation scripts and the shared evaluation harness;
- the benchmarks in their original and rebuilt forms, including the audits that invalidated the
  originals;
- the metric-control validation of the faithfulness metric;
- the latency and cold-start harness and its raw measurements;
- the generated answers of the ablation and attribution runs with their unit-level NLI labels;
- an export that ties every number cited in the manuscript to a file, a JSON path and a hash.

Two items are not included, for different reasons. The platform implementation is withheld because
it is subject to ongoing technology-transfer negotiations. The corrected routing read-back is
withheld because it is a modified copy of the platform's solver; its results are included in
`ilp_fix/results/`. As a result, the package supports independent inspection and re-analysis of
every reported value, but not re-execution of the deployed system.

## Dataset information

| Dataset | Location | Size | Origin |
|---|---|---|---|
| SynConflict v1 (superseded) | `synconflict_v1/data/instances.jsonl` | 100 pairs (50 conflicting, 50 not) | Generated by `synconflict_v1/build_conflict_set.py`, seed 42. Kept on purpose: its generator was built so that the deployed threshold is optimal |
| SynConflict v2 (rebuilt) | `synconflict_v2/data/instances.jsonl` | 600 pairs (300 conflicting, 300 not) | Generated by `synconflict_v2/build_synconflict_v2.py`, seed 42. Both texts of a pair share one register by default; a cross-register group (25% of pairs) measures the register effect separately |
| External contradiction samples | `external_eval/data/` | 1,000 pairs per class per corpus | Samples of SNLI, MultiNLI and VitaminC, redistributed under the licences of those datasets |
| Ablation evaluation set | `ablation_v2/data/evalset.jsonl` | 60 queries; the reported runs use the first 30 | Built by `ablation_v2/build_evalset.py` from 50 KLUE news and encyclopedia passages (CC BY-SA 4.0), three source chunks per query |
| Attribution evaluation set | `mars_attribution/data/evalset_mars.jsonl` | 60 queries; the reported runs use the first 30 | Built by `mars_attribution/build_mars_evalset.py` from the ablation set: two relevant and three distractor chunks per query |
| MultiTurnSet v2 | `hmmr_v2/data/` | 137 segments, 157 turns; three assembled runs (seeds 0, 1, 2) | Built from KLUE news and encyclopedia passages, ten arXiv papers and ten chart images. Segments quote the sources under their original licences; the source documents themselves are not included |
| Generated answers and unit-level NLI labels | `ablation_v2/results/`, `mars_attribution/results/` (`raw_records.jsonl`, `unit_labels.jsonl`) | 360 ablation records (30 queries × 4 configurations × 3 orderings) and 90 attribution records (30 queries × 3 orderings) | Answers generated by the deployed language model (Qwen2.5-7B-Instruct) under the deployed prompts |
| Latency and cold-start measurements | `latency/results*/` | one original run and two re-runs | Measured on Ubuntu 22.04, CUDA 12.1, NVIDIA A100 80 GB PCIe |
| Number export | `export/paper_numbers.csv`, `export/manifest.json` | 278 values | Every value the manuscript cites, with source file, JSON path and SHA-256 prefix |

All JSON and JSONL files are UTF-8. Apart from the SNLI, MultiNLI and VitaminC samples, the
benchmark instances, evaluation queries and generated answers are in Korean, because the audited
system serves Korean users.

Comments, docstrings and console messages are in English. String literals that are inputs to the
experiments or that process Korean text are kept in Korean: the benchmark templates in the
SynConflict generators, the query templates of the ablation set, the synthetic session texts and
queries of the latency and sensitivity harnesses, the prompts of the deployed system, and the
Korean sentence-splitting and negation rules of the faithfulness metric. Translating them would
change the benchmarks and the measured behaviour. English renderings of the deployed prompts are
given in Supplemental Article S1 (§S6) of the article.

## Usage instructions

Run every command from the package root.

### Check every reported number

```bash
python export_paper_numbers.py
```

Rewrites `export/paper_numbers.csv` (278 values) from the shipped artifacts. The `value` column
must be unchanged. The SHA-256 prefixes refer to the internal copies of the artifacts, which differ
from the shipped ones only in redacted provenance fields (host names, local paths, branch names), so
that column may differ while the values do not.

### Re-run the analyses

```bash
python ablation_v2/analyze_results.py          # ablation statistics -> ablation_v2/results/analysis.json, analysis_table.csv
python mars_attribution/analyze_query_level.py # attribution, query level -> mars_attribution/results/query_level.json
python hmmr_v2/analyze.py                      # memory retrieval -> hmmr_v2/results/analysis.json
python figures/regen_figs.py                   # Figures 2 and 3 -> figures/out/
```

### Re-derive the NLI labels and validate the metric (GPU recommended)

```bash
python unit_labels/export_unit_labels.py   # fails unless every per-answer aggregate equals the stored one
python ablation_v2/validate_metric.py      # metric-control validation -> ablation_v2/results/metric_validation.json
```

### Rebuild the benchmarks

```bash
python synconflict_v1/build_conflict_set.py --n 100 --seed 42 --output synconflict_v1/data
python synconflict_v2/build_synconflict_v2.py --n 600 --seed 42
python mars_attribution/build_mars_evalset.py --seed 42
python hmmr_v2/assemble.py --seeds 0 1 2
```

These reproduce the shipped instances; only the `created_at` timestamps in the `metadata.json`
files change. `ablation_v2/build_evalset.py`, `hmmr_v2/build_segments.py` and `hmmr_v2/gen_llm.py`
read source passages and papers from `../experiments/datasets/raw/`, which are not redistributed;
`hmmr_v2/gen_llm.py` also needs vLLM and the Qwen models. Their outputs are shipped in the
respective `data/` directories.

### Scripts that need the platform

The evaluation harnesses import the platform's gateway package at run time
(`common/harness.py`, `bootstrap_gateway`), so that they measure the deployed code rather than a
reimplementation. They do not run without it: `synconflict_v2/evaluate_cmae_v2.py`,
`external_eval/run_external_eval.py`, `common/cmae_eval.py`, `sensitivity/*`,
`ablation_v2/run_ablation.py`, `mars_attribution/run_mars_eval.py`, `hmmr_v2/run_hmmr_v2.py`,
`hmmr_v2/audit_dataset.py` and `config_snapshot/snapshot_registry.py`. `latency/*` additionally
needs the platform's services (language and speech containers, vector store);
`latency/docker-compose.latency.yml` documents the overlay used. Their inputs and raw outputs are
shipped, so every reported number can be re-derived without re-running them.

## Methodology

1. **Benchmarks.** Synthetic conflict pairs, evaluation queries and multi-turn sessions are
   generated with fixed seeds. Each rebuilt benchmark comes with an audit that checks the property
   the original violated (register matched within pairs, with a cross-register control group, for
   SynConflict v2; a contingency test of probe and target modality for MultiTurnSet v2).
2. **Measurement.** The harnesses call the deployed code and record every run with a provenance
   block (timestamp, code commit, Python version, GPUs; host-specific fields are redacted in the
   shipped copies). Latency is measured with a sequential, instrumented harness on one A100 80 GB
   card: 30 measured iterations after 5 warm-up iterations, cycling over three fixed queries, with
   a per-iteration nonce in the conflict-screening and attribution inputs so that the embedding
   cache cannot serve a previous result.
3. **Metric calibration.** The entailment model and premise granularity of the NLI faithfulness
   metric are fixed against three control conditions with known expected values (answers copied
   from their sources, answers from unrelated documents, answers negating their sources; 15
   instances each) before the metric is used to compare configurations.
4. **Statistics.** Comparisons that share inputs are paired. The unit of analysis is the query
   (ablation and attribution, n=30) or the target turn (memory, 157 targets). Results are reported
   as the mean paired difference with a percentile bootstrap 95% interval (10,000 resamples, fixed
   seed). The ablation and memory contrasts add a two-sided sign-flip permutation test (100,000
   draws); attribution is compared against random and within-query-shuffle baselines.
5. **Export.** `export_paper_numbers.py` reads every cited value from its artifact by JSON path and
   writes it with the artifact's hash, so that each number in the manuscript can be traced to a
   file.

Unit-level NLI labels were not captured during the original runs. They were recomputed from the

attribution records). Runs discarded as invalid are not shipped.
